Part 1: Mathematical Foundation

1.1 Core Problem Statement

At the heart of any dynamic pricing system lies a fundamental mapping problem. Given a price point $P$ for a service (whether voice minutes, data megabytes, or SMS messages), we must determine the volume $V$ of units a customer receives:

$f: P \mapsto V$

The mathematical challenge here is substantial: this function is non-linear, piecewise-defined, and must simultaneously incorporate multiple business constraints including validity periods, promotional discounts, and bundle economics.

1.2 The Effective Rate Model

The central innovation of this pricing engine is the concept of an Effective Rate (ER) — representing the price per unit at any given price point. This abstraction allows us to decompose complex pricing logic into manageable components:

$ER(P) = \frac{P}{V(P)} \quad \implies \quad V(P) = \frac{P}{ER(P)}$

Exponential Decay Pattern

The effective rate follows a carefully calibrated exponential decay pattern that captures the economic reality of diminishing marginal utility:

$ER(P) = r_{floor} + (r_{anchor} - r_{floor}) \cdot e^{-k(P - P_{anchor})}$

1.3 Derivation of the Decay Constant k

To fully specify our exponential model, we must derive the decay constant $k$ from boundary conditions. From the configuration parameters, we establish three critical constraints:

  • At $P = P_{anchor}$: The effective rate equals $ER = r_{anchor}$
  • As $P \to \infty$: The effective rate approaches its asymptote $ER \to r_{floor}$
  • At $P = P_{max}$: We define $ER = r_{floor} + \epsilon$ where $\epsilon = 0.01$ ensures numerical behavior

Solving the exponential equation for $k$:

$$\begin{aligned} r_{floor} + \epsilon &= r_{floor} + (r_{anchor} - r_{floor}) \cdot e^{-k(P_{max} - P_{anchor})} \\[10pt] \frac{\epsilon}{r_{anchor} - r_{floor}} &= e^{-k(P_{max} - P_{anchor})} \\[10pt] \ln\left(\frac{\epsilon}{r_{anchor} - r_{floor}}\right) &= -k(P_{max} - P_{anchor}) \end{aligned}$$
$\displaystyle k = -\frac{\ln\left(\frac{\epsilon}{r_{anchor} - r_{floor}}\right)}{P_{max} - P_{anchor}}$
PYTHON IMPLEMENTATION
@staticmethod
def recalculate_decay(anchor_price, anchor_rate, floor_rate, max_price):
    # Validate inputs to prevent undefined behavior
    if anchor_rate <= floor_rate or max_price <= anchor_price:
        return math.nan
    
    # Define epsilon tolerance for numerical stability
    rate_at_max = floor_rate + 0.01
    
    # Apply logarithmic derivation formula
    numerator = math.log(
        (rate_at_max - floor_rate) / (anchor_rate - floor_rate)
    )
    denominator = max_price - anchor_price
    
    return -numerator / denominator

Part 2: Piecewise Linear Interpolation

While the exponential decay model provides elegant theoretical foundations, real-world pricing systems require handling empirical data points that may not perfectly fit any parametric curve. This necessitates piecewise linear interpolation.

2.1 Mathematical Formulation

Given a set of $n$ known data points $(x_1, y_1), (x_2, y_2), \ldots, (x_n, y_n)$ sorted by $x$-coordinate, for any query value $x$ we compute:

$y(x) = y_i + \frac{(y_{i+1} - y_i)}{(x_{i+1} - x_i)}(x - x_i) \quad \text{where } x_i \leq x < x_{i+1}$

2.2 Boundary Condition Handling

Left Extrapolation (x < x₁)

When the query falls below our lowest data point, we extrapolate using the slope between the first two points:

$y(x) = y_1 + \frac{(y_2 - y_1)}{(x_2 - x_1)}(x - x_1)$

Right Saturation (x ≥ xₙ)

When the query exceeds our highest data point, we return the final known value (constant extrapolation):

$y(x) = y_n$
INTERPOLATION ALGORITHM
@staticmethod
def interpolate(x, points):
    # Handle left boundary: extrapolate using initial slope
    if x < points[0][0]:
        x1, y1 = points[0]
        x2, y2 = points[1]
        slope = (y2 - y1) / (x2 - x1) if (x2 - x1) != 0 else 0
        return y1 + (x - x1) * slope
    
    # Find containing interval via linear scan
    for i in range(len(points) - 1):
        x1, y1 = points[i]
        x2, y2 = points[i + 1]
        if x1 <= x < x2:
            return y1 + (x - x1) * (y2 - y1) / (x2 - x1)
    
    # Right boundary: return last known value
    return points[-1][1]

Part 3: Service-Specific Pricing Functions

The dynamic pricing engine implements distinct mathematical formulations for each service type, reflecting different consumption patterns and business requirements.

3.1 Voice Service — Dual Time-Horizon Model

Voice pricing uniquely supports both daily and weekly validity periods, each with dedicated empirical data points:

Daily Validity (validity ≠ 7 days)

$$ER_{voice}(P) = \begin{cases} \text{Interpolate}(P, \text{daily\_points}) \times VPM(d) & P \leq P_{last}^{daily} \\[10pt] \left[r_{floor} + (ER_{last}^{daily} - r_{floor}) \cdot e^{-k(P - P_{last}^{daily})}\right] \times VPM(d) & P > P_{last}^{daily} \end{cases}$$

Weekly Validity (validity = 7 days)

$$ER_{voice}(P) = \begin{cases} \text{Interpolate}(P, \text{weekly\_points}) & P \leq P_{last}^{weekly} \\[10pt] r_{floor} + (ER_{last}^{weekly} - r_{floor}) \cdot e^{-k(P - P_{last}^{weekly})} & P > P_{last}^{weekly} \end{cases}$$

Note: Weekly rates already embed validity premiums internally, so no separate VPM multiplier is applied.

3.2 Data Service — Hybrid Anchor Transition

Data pricing uses a hybrid approach where the anchor price serves as the transition point between interpolation and exponential decay:

$$ER_{data}(P) = \begin{cases} \text{Interpolate}(P, \text{daily\_points}) \times VPM(d) & P \leq P_{anchor} \\[10pt] \left[r_{floor} + (r_{anchor} - r_{floor}) \cdot e^{-k(P - P_{anchor})}\right] \times VPM(d) & P > P_{anchor} \end{cases}$$

3.3 SMS Service — Pure Exponential Decay

SMS uses the simplest formulation with pure exponential decay from the anchor point:

$ER_{sms}(P) = \left[r_{floor} + (r_{anchor} - r_{floor}) \cdot e^{-k(P - P_{anchor})}\right] \times VPM(d)$

Part 4: Validity Premium Multiplier (VPM)

Longer validity periods represent greater value to customers and consequently command a premium on the effective rate. This is implemented through the Validity Period Multiplier.

4.1 Mathematical Definition

$VPM(d) = 1 + \frac{\text{Premium}(d)}{100}$

4.3 Interpolated VPM for Arbitrary Validity

For validity durations not explicitly configured, the system performs linear interpolation between the nearest defined points:

WORKED EXAMPLE: 5-Day Validity

Given points: [(1, 0%), (3, 50%), (7, 120%)]

Finding interval: 5 falls between 3 and 7

$$\begin{aligned} Premium(5) &= 50 + \frac{120 - 50}{7 - 3}(5 - 3) \\[8pt] &= 50 + \frac{70}{4} \times 2 \\[8pt] &= 50 + 35 = \mathbf{85\%} \end{aligned}$$

Result: $VPM(5) = 1 + 0.85 = \mathbf{1.85}$

Part 5: Multiplicative Discount Architecture

The final effective rate incorporates three multiplicative discount factors, enabling flexible composition of various promotional and structural adjustments:

$ER_{final} = ER_{base} \times MBDF \times TDF$

📦 MBDF — Mixed Bundle Discount Factor

Applies when customers purchase multiple services simultaneously:

$MBDF = 1 - \frac{mbdf\_per \times BD(n)}{100}$

Where $BD(n)$ is the bundle discount percentage based on number of services $n$, and $mbdf\_per$ is a binary flag (0 or 1).

🏷️ TDF — Transaction Discount Factor

Captures channel-specific and campaign-specific pricing adjustments:

$TDF = 1 - \frac{discount}{100}$

Varies by offer type: ATL, DIY mode, promotions, or BTL tiers.

Part 6: Complete Volume Calculation Algorithm

We now synthesize all components into the complete algorithm that transforms a price input into a volume output.

ALGORITHM: CalculateVolumeFromPrice

Compute MBDF
$MBDF = 1 - \frac{mbdf\_per \times BD(n)}{100}$
Compute TDF
If promotion conditions met: $TDF = 1 - \frac{promo\_discount}{100}$
Otherwise: $TDF = 1 - \frac{btl\_discount}{100}$
Compute Base Effective Rate
Select formula based on service type:
• Voice: Interpolation → Decay (with optional VPM)
• Data: Hybrid anchor-based selection
• SMS: Pure exponential decay
Apply Validity Premium
$ER_{base} = ER_{raw} \times VPM(validity\_days)$
Apply Discount Factors
$ER_{final} = ER_{base} \times MBDF \times TDF$
Compute Final Volume
$V = \frac{P}{ER_{final}}$

6.1 Worked Example: Voice Purchase

SCENARIO

Price: ₹500 | Service: Voice | Validity: 3 days | Mode: Single service, BTL Normal

Step-by-Step Calculation:

Step 1 — MBDF: $1.0$ (single service, no bundle discount)

Step 2 — TDF: $1 - 20/100 = \mathbf{0.80}$ (btl_normal)

Step 3 — Base ER (Interpolation):

  • Price 500 falls between [450, ₹8.82/min] and [540, ₹8.44/min]
  • $ER = 8.82 + \frac{8.44 - 8.82}{540 - 450}(500 - 450)$
  • $ER = 8.82 + (-0.00422)(50) = 8.82 - 0.211 = \mathbf{8.609}$

Step 4 — Apply VPM: $VPM(3\text{ days}) = 1.50$

$ER_{base} = 8.609 \times 1.50 = \mathbf{12.914}$

Step 5 — Final ER: $12.914 \times 1.0 \times 0.80 = \mathbf{10.331}$

Step 6 — Volume: $V = 500 / 10.331 = \mathbf{48.4 \approx 48 \text{ minutes}}$

Part 7: The Inverse Problem — Binary Search

7.1 Problem Formulation

In many scenarios (particularly "build your bundle" interfaces), we need to solve the inverse problem: given a target volume $V^*$, find the price $P^*$ such that:

$\text{CalculateVolume}(P^*) = V^*$

Since our pricing function is non-analytic (piecewise-defined with conditional logic), we cannot derive a closed-form inverse. Instead, we employ binary search (bisection method).

7.2 Binary Search Algorithm

ALGORITHM: FindPriceForVolume

Initialize Bounds
$low = 0.01$, $high = P_{max}$
Iterate (up to 100 iterations)
$guess = \frac{low + high}{2}$
$volume = \text{CalculateVolume}(guess)$
Apply rounding rules to volume
Update Bounds
If $rounded\_volume < V^*$: $low = guess$ (need higher price)
Else: $high = guess$ (need lower price)
Convergence Check
If $(high - low) < 0.001$: BREAK
Return $high$ as final price

7.3 Convergence Analysis

Binary search on interval $[0.01, P_{max}]$ with tolerance $\epsilon = 0.001$:

$$\begin{aligned} \text{Iterations Required} &= \left\lceil \log_2\left(\frac{P_{max} - 0.01}{\epsilon}\right)\right\rceil \\[10pt] &= \left\lceil \log_2\left(\frac{9999.99}{0.001}\right)\right\rceil \\[10pt] &= \lceil \log_2(9,999,990) \rceil \approx \mathbf{24 \text{ iterations}} \end{aligned}$$

The algorithm allocates 100 iterations as an upper bound — more than sufficient for convergence while maintaining computational efficiency.

Part 9: Mathematical Properties & Proofs

9.1 Monotonicity Theorem

Theorem: $V(P)$ is Strictly Monotonically Increasing

Proof:

  1. $ER(P)$ is strictly decreasing (exponential decay with negative exponent, or decreasing linear interpolation)
  2. $V(P) = P / ER(P)$
  3. Differentiating: $\displaystyle\frac{dV}{dP} = \frac{ER - P \cdot ER'}{ER^2}$
  4. Since $ER' < 0$ (decreasing function) and $ER > 0$ always:
  5. Numerator: $ER - P \cdot ER' > ER > 0$ ✓
  6. Denominator: $ER^2 > 0$ ✓
  7. Therefore: $\frac{dV}{dP} > 0$ everywhere

Corollary: Binary search is guaranteed to converge to unique solution.

9.2 Continuity Analysis

The composite function $V(P)$ is continuous at all transition points:

  • Interpolation → Decay boundary: Both formulas evaluate to identical values at the junction point by construction
  • Validity transitions: VPM provides continuous scaling without discontinuities
  • Discount application: Multiplicative factors preserve continuity

9.3 Concavity Property

$V(P)$ is concave (exhibiting diminishing returns):

  • Each additional rupee yields fewer additional units than the previous rupee
  • This aligns with standard economic intuition for bulk discounting
  • Mathematically: $\frac{d^2V}{dP^2} < 0$ for typical parameter ranges
