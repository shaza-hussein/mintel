AI Telecom Bundle Generation System

Architecture for GA-based bundle discovery, controlled naming, and final popularity scoring.

This page documents the exact solution: new telecom bundle structures are generated with a genetic algorithm, each generated structure receives a deterministic placeholder name so it can be scored by the current popularity model, then strong structures move to LLM-based final naming, validation, and final rescoring.

System objective

Generate new telecom bundles that maximize a predicted popularity score, where higher popularity is used as a signal for stronger expected revenue, better customer retention, and better market acceptance.

Genetic Algorithm Placeholder Naming LLM Name Generation Popularity Prediction Dynamic Pricing Authority

Core dependency

The popularity model depends on both structured features and bundle_name embeddings. Because of that, a generated structure cannot be scored without some name. The solution is to use a controlled placeholder name during optimization, then use the LLM only after top structures are found.

Overview

1. What the system does

01

The system is designed to automatically discover and evaluate candidate telecom bundles such as data bundles, voice bundles, SMS bundles, and mixed bundles using bundle fields like bundle_type, price, usage_type, service_class_category, configured_volume_mb, configured_volume_min, configured_volume_sms, and validity_hours.

Stage 1

GA generates and improves new bundle structures.

Name bridge

Placeholder naming makes each generated structure scorable by the current model.

Stage 2

LLM generates realistic commercial names only for promising structures.

Final step

The popularity model rescoring step chooses the best final bundle-name pair.

Problem Definition

2. Why a hybrid pipeline is needed

02

Large search space

The bundle search space is large because it mixes categorical variables, numeric variables, and realistic business constraints. Manual rule design is not enough to explore this space efficiently.

Model dependency on text

The popularity model uses sentence embeddings of bundle_name, PCA on those embeddings, and scaled numeric features. That means structure-only candidates are not directly scorable.

Need for realism

The system must generate bundles that are not only high-scoring but also commercially interpretable, realistic, and consistent with telecom naming style.

Key design question

If the GA generates only a new bundle structure, what is the bundle name used during scoring? The answer in this solution is: every generated structure receives a deterministic placeholder name before it is passed into the popularity model.

System Architecture

3. Main system components

03

Historical data

Historical bundles are used to train the popularity model, define realistic feature ranges, seed the GA population, and provide style examples for final bundle naming.

Bundle structure generator

The genetic algorithm generates candidate bundle structures using initialization, selection, crossover, mutation, and repair.

Placeholder name generator

A deterministic function converts a generated structure into a basic and consistent name so the current popularity model can score it.

Popularity scoring model

The trained model predicts popularity using structure, placeholder or final bundle name, and time-based fields such as week_number and season.

LLM name generator

After strong structures are identified, the LLM generates realistic commercial bundle names that follow the operator naming style.

Name validator and reranker

The validator checks name consistency, then the final scorer reranks valid bundle-name combinations and keeps the best offers.

Stage 1

5. Genetic algorithm for bundle structures

05

Why GA fits this problem

  • The bundle design problem mixes categorical and numeric variables.
  • The search space is large and does not have a simple differentiable objective.
  • A predictive popularity model already exists and can be used as the fitness evaluator.
  • The GA can discover novel combinations beyond the historical catalog.

Chromosome definition

  • bundle_type
  • price
  • usage_type
  • service_class_category
  • configured_volume_mb
  • configured_volume_min
  • configured_volume_sms
  • validity_hours

Initialization

The initial population should combine real historical bundles with random but valid synthetic bundles that stay within realistic operator ranges. This balances realism with diversity.

Evolution operators

Selection keeps stronger candidates. Crossover combines features from parent bundles. Mutation perturbs fields like price, validity, data volume, voice minutes, or SMS count. Repair keeps bundles valid after changes.

Fitness design in Stage 1

The Stage 1 fitness function uses the popularity model with the generated structure plus its placeholder name. Conceptually: fitness(candidate_structure) = popularity_model(candidate_structure + placeholder_name) - penalties. Penalties can cover invalid combinations, unrealistic bundle ratios, out-of-range values, or business-policy violations.

Placeholder Naming

6. The bridge that makes generated structures scorable

06

Why placeholder naming is required

  • The popularity model expects a bundle_name input.
  • Generated structures cannot be scored if they have no name.
  • A deterministic naming bridge keeps optimization stable.
  • It avoids using the LLM inside every GA evaluation.

How the placeholder should behave

  • Deterministic.
  • Consistent with the actual bundle fields.
  • Realistic enough to resemble telecom naming style.
  • Not creative and not overly variable.
Bundle type Placeholder example Purpose
Data bundle Forfait Data 5GB 7 jours@1500F Produces a realistic, model-compatible name from the structure.
Voice bundle Forfait Voix 100Min 30 jours@1200F Keeps the naming style aligned with the training distribution.
Mix bundle Forfait Mix 2GB + 50Min + 20SMS 7 jours@2500F Includes only the resources actually present in the generated structure.
Why not use blank or dummy names

Names like bundle_001, test_name, or candidate_offer would distort the popularity model input because the model was trained on telecom-like names. The placeholder must therefore stay close to the naming style seen during training.

Stage 2

7. LLM-based final name generation

07

Role of the LLM

The LLM is used only after the GA has identified promising bundle structures. Its role is to generate realistic, commercially attractive, human-readable final names, not to act as the main optimizer.

LLM inputs

  • Bundle type
  • Data volume
  • Voice minutes
  • SMS volume
  • Validity
  • Price to be considered for the final offer
  • Usage type and naming style examples

LLM outputs

For each selected structure, the LLM should generate multiple candidate names such as 3, 5, or 10 variants. This gives controlled variation without letting free text drive the GA loop.

Example naming behavior

For a bundle with bundle_type = BUNDLE_DATA, configured_volume_mb = 5120, validity_hours = 168, and price = 1500, possible names include Forfait Internet 5GB 7 jours@1500F, Pack Data 5GB Hebdo@1500F, and Forfait 5GB 7 jours@1500F.

Validation

8. Final name validation and rescoring

08

Why validation is required

LLM-generated names can mention wrong quantities, invent features, mismatch validity, or use unrealistic wording. Every generated name must be validated before it is accepted.

Validation rules

  • If configured_volume_mb == 0, the name must not mention MB or GB.
  • If configured_volume_min == 0, the name must not mention minutes.
  • If configured_volume_sms == 0, the name must not mention SMS.
  • The name must include the correct price and match the actual validity.
  • Unlimited or Illimite must only be used when valid.

Final reranking

Once valid names are generated, the final bundle-name pairs are rescored by the popularity model and the best final offers are kept.

Evaluation

11. Advantages, risks, and safeguards

11

Advantages

  • Works with the current popularity model.
  • Placeholder naming keeps early scoring stable.
  • The LLM is used where it adds value most: final commercial naming.
  • The system remains interpretable because structure scoring and final naming are separated.

Risks

  • Text still influences the final score because the model uses name embeddings.
  • Bundles too far from the historical distribution may be less reliable.
  • Even after validation, some LLM names may still be awkward.
  • The popularity model predicts expected performance, not guaranteed market success.

Safeguards

  • Use realistic business constraints and repair rules.
  • Keep placeholder naming deterministic during GA evolution.
  • Generate multiple final names and select the best valid one.
  • Log both structure-level and final rescored outputs for review.
Conclusion

12. Final recommended solution

12

The final recommended solution is to use a genetic algorithm to generate and optimize telecom bundle structures, attach a deterministic placeholder bundle name so the current popularity model can score those structures, use the trusted dynamic pricing model as the final price authority to be considered for the commercial offer, generate realistic final names with an LLM, validate those names carefully, and rescore the final bundle-name pairs before selecting the best offers.

The key idea that keeps the system coherent is simple: generated bundle structures must receive a placeholder name during optimization because the current popularity model requires bundle_name. The trusted dynamic pricing model is then layered into the same architecture as the authoritative commercial pricing source, while any GA-generated price stays additional.
