MinTel Bundle Generation Engine

Predictive Bundle Optimization with Genetic Search

This document explains the proposed MinTel bundle generation solution in detail. The solution keeps the existing Dynamic Pricing Algorithm unchanged, predicts the business popularity of a bundle from historical bundle data, uses a Genetic Algorithm to search for better bundle structures under telecom business constraints, subtracts cannibalization risk from the objective, and finally uses an LLM only for naming and presentation.

Pricing Rule All prices come only from the Dynamic Pricing Algorithm.
Main Search Method Genetic Algorithm over bundle structure space.
Main Prediction Target Business popularity score based on revenue and contribution margin.
LLM Role Name and describe bundles after optimization only.
01

Solution Summary

The system starts from the operator's current portfolio and a historical bundle dataset. It trains a model that estimates how commercially strong a candidate bundle is. Then a Genetic Algorithm searches for improved bundle structures while respecting telecom business constraints. Each candidate is priced by the existing pricing engine. A cannibalization module penalizes candidates that steal value from current bundles. After the best structures are found, an LLM generates names aligned with the operator's brand and bundle culture.

Why This Approach Is Feasible

  • It keeps pricing unchanged, which reduces risk.
  • It uses historical operator knowledge instead of requiring full generative bundle design from day one.
  • It uses structured optimization rather than free-text generation.
  • It is easy to implement as an MVP and improve later.

What the Engine Produces

  • new bundle structures
  • business popularity score
  • price from pricing engine
  • cannibalization penalty
  • final optimized fitness score
  • bundle name and commercial description
02

System Pipeline

The bundle generation engine is a structured multi-stage pipeline. Each stage has one clear role.

Stage 1

Historical Learning

Train a business popularity model using historical bundle attributes and historical bundle outcomes.

Stage 2

Candidate Search

Use Genetic Algorithm to generate and evolve bundle structures under business constraints.

Stage 3

Commercial Evaluation

Price every candidate, predict business popularity, and subtract cannibalization penalty.

Stage 4

Presentation

Pass top bundle structures to the LLM to create bundle names and market-friendly descriptions.

Key design principle: the LLM is not the optimization engine. The optimization engine is the Genetic Algorithm guided by predictive scoring.
03

Bundle Representation

To optimize bundles, each bundle must be encoded in a structured feature vector. The Genetic Algorithm cannot work on free text.

Bundle x = [segment, plan_type, validity, data_gb, voice_min, sms_count, social_flag, video_flag, rollover_flag, roaming_flag, speed_tier, renewal_bonus, target_objective, ...]

Core Structural Features

  • data allowance
  • voice minutes
  • SMS allowance
  • validity period
  • speed or fair usage policy

Commercial and Marketing Features

  • target segment
  • prepaid or postpaid
  • strategic objective
  • bonus type
  • brand style tag

Optional Enrichment Features

  • estimated usage class
  • network stress class
  • competitor matching type
  • bundle family code
  • portfolio similarity tag
04

Popularity Model

The popularity model predicts how commercially strong a bundle is based on historical bundle data. In your updated idea, popularity is not simple subscription count. It is a value-oriented score driven by revenue and contribution margin.

Historical Dataset

Each historical bundle record should include:

  • bundle structure features
  • official launch price
  • subscription count
  • generated revenue
  • contribution margin
  • target segment
  • bundle family or commercial category
  • launch period if available

Business Popularity Score

For historical bundle i: Revenue_i = total revenue generated by bundle i Margin_i = contribution margin generated by bundle i Normalized_Revenue_i = (Revenue_i - min(Revenue)) / (max(Revenue) - min(Revenue)) Normalized_Margin_i = (Margin_i - min(Margin)) / (max(Margin) - min(Margin)) Popularity_i = alpha * Normalized_Revenue_i + beta * Normalized_Margin_i where: alpha >= 0, beta >= 0, and often alpha + beta = 1
Interpretation: a higher popularity score means the bundle is commercially stronger, not just more subscribed.

Prediction Function

Given bundle feature vector x: Predicted_Popularity(x) = f(x) where f can be any supervised regression model trained on historical bundles.

Simple Model Choices

  • Linear Regression
  • Ridge Regression
  • Random Forest Regressor
  • XGBoost Regressor

Best Practical Choice

Gradient-boosted tree models are usually a strong choice because bundle features are mixed, non-linear, and may interact.

MVP Advice

Start with a simple interpretable model first, then move to a stronger model if needed.

05

Dynamic Pricing Integration

The pricing engine remains unchanged. It acts as a pricing oracle for every generated bundle candidate.

For every generated candidate bundle x: Price(x) = DP(x) where DP is the existing Dynamic Pricing Algorithm.

Role of the Pricing Engine

  • assign official commercial price
  • keep pricing logic consistent
  • reduce design risk
  • make optimization focus on structure, not price guessing

Role of Bundle Engine

  • generate bundle structure
  • request price from DP
  • predict popularity using bundle plus official price
  • evaluate cannibalization and final fitness
06

Genetic Algorithm

The Genetic Algorithm searches the space of possible bundle structures. It starts from the current operator portfolio so the search begins with realistic telecom bundles.

Population at generation t: P^(t) = { x_1^(t), x_2^(t), ..., x_N^(t) } where each x_k^(t) is a candidate bundle structure.

Initial Population

The initial population is seeded from:

  • current operator portfolio bundles
  • slight variations of existing bundles
  • valid random bundles within constraints

GA Operators

  • Selection: choose stronger bundles for reproduction
  • Crossover: combine two parent bundles
  • Mutation: randomly alter one or more bundle genes
  • Elitism: keep top candidates across generations

Constraint Handling

A candidate bundle x is feasible only if: g_j(x) <= 0 for inequality constraints h_k(x) = 0 for equality constraints Examples: - price must be valid - data allowance must be within allowed range - validity must be in allowed set - bundle must respect segment rules - bundle must not violate telecom policy
Constraint Type Examples
Structural Allowed validity days, allowed data ranges, allowed voice ranges, legal feature combinations.
Commercial No forbidden low-value combinations, no off-brand bundles, no invalid market segment assignments.
Operational No non-fulfillable offers, no impossible benefit combinations, no disallowed network-heavy features if restricted.
07

Cannibalization Model

Cannibalization is added as a penalty. A new bundle may look attractive but simply move customers away from an existing profitable bundle instead of creating real new value.

Pairwise Cannibalization Risk

For generated bundle x and existing portfolio bundle e: CannRisk(x, e) = Sim(x, e) * Overlap(x, e) * Attr(x, e) * Importance(e) where: Sim(x, e) = structural similarity Overlap(x, e) = audience overlap Attr(x, e) = substitution attractiveness Importance(e) = business importance of existing bundle e

Sim(x, e)

How structurally similar the two bundles are.

Overlap(x, e)

How much they target the same customer group or same use case.

Attr(x, e)

Whether the new bundle is a better substitute at a similar price.

Importance(e)

How valuable the existing bundle is to the operator.

Structural Similarity

One simple similarity form: Sim(x, e) = w1*S_segment + w2*S_validity + w3*S_data + w4*S_voice + w5*S_bonus + w6*S_priceband where each S_term is in [0, 1] and sum(wi) = 1

Audience Overlap

Overlap(x, e) in [0,1] Examples: - same target segment -> high overlap - same use case -> high overlap - very different use case -> low overlap

Substitution Attractiveness

Define a value density: ValueDensity(x) = BenefitScore(x) / Price(x) Then: Attr(x, e) = max(0, ValueDensity(x) - ValueDensity(e)) normalized to [0,1]

Existing Bundle Importance

Importance(e) = u1 * RevShare(e) + u2 * MarginShare(e) + u3 * SubsShare(e) where: RevShare(e) = normalized revenue share of existing bundle e MarginShare(e) = normalized contribution margin share of existing bundle e SubsShare(e) = normalized subscriber share of existing bundle e

Total Cannibalization Penalty

For candidate bundle x: CannPenalty(x) = sum over all existing bundles e in portfolio E of CannRisk(x, e)
Meaning: the more a candidate bundle threatens strong existing bundles, the larger the penalty and the lower its final fitness.
08

Final Fitness Function

The Genetic Algorithm should optimize net business value, not popularity alone.

For candidate bundle x: Fitness(x) = a * Predicted_Popularity(x) - b * CannPenalty(x) - c * ComplexityPenalty(x) - d * ConstraintPenalty(x) where: a, b, c, d >= 0

Expanded Form

Predicted_Popularity(x) = alpha * Normalized_Predicted_Revenue(x) + beta * Normalized_Predicted_Margin(x) Fitness(x) = a * [ alpha * Normalized_Predicted_Revenue(x) + beta * Normalized_Predicted_Margin(x) ] - b * CannPenalty(x) - c * ComplexityPenalty(x) - d * ConstraintPenalty(x)

Popularity Part

Rewards bundles that are expected to perform well commercially.

Cannibalization Part

Punishes bundles that are likely to steal value from current successful bundles.

Penalty Part

Punishes bundles that are too complex or violate business constraints.

Complexity Penalty Example

ComplexityPenalty(x) = m1 * NumFeatures(x) + m2 * BonusComplexity(x) + m3 * CatalogRedundancy(x)

Constraint Penalty Example

ConstraintPenalty(x) = 0, if x is feasible LargePositiveValue, if x is infeasible or softer: ConstraintPenalty(x) = sum_j max(0, g_j(x))

Mathematical Flow of One Candidate Bundle

This is the clean mathematical sequence for evaluating one generated bundle candidate.

Step 1: Candidate structure x -> generated by GA Step 2: Official price p = DP(x) Step 3: Feature vector for prediction z = concat(x, p) Step 4: Business popularity prediction B(x) = f(z) Step 5: Cannibalization penalty C(x) = sum_e CannRisk(x, e) Step 6: Other penalties K(x) = ComplexityPenalty(x) V(x) = ConstraintPenalty(x) Step 7: Final fitness F(x) = a * B(x) - b * C(x) - c * K(x) - d * V(x)
Interpretation: the final winner is not just the bundle with the highest raw business potential. It is the bundle with the highest net value after subtracting risks and penalties.
11

LLM Naming Layer

After optimization, the LLM is used to generate human-friendly bundle names and descriptions. This keeps the LLM in a safe presentation role.

LLM Input

  • generated bundle structure
  • official price
  • target segment
  • operator naming style
  • bundle family examples from current portfolio

LLM Output

  • bundle name
  • short marketing description
  • commercial summary
  • optional internal explanation
LLM_prompt = { bundle_structure, price, target_segment, operator_bundle_culture, naming_examples } LLM_output = { bundle_name, bundle_description, commercial_pitch }

13

Advantages and Limitations

This solution is strong for an MVP and a graduation project because it is practical and expandable.

Advantages

  • feasible to implement
  • keeps pricing stable
  • uses structured optimization
  • easy to explain mathematically
  • easy to improve later with better models
  • LLM is used in a low-risk role

Limitations

  • historical bundle data may bias the model toward old product logic
  • cannibalization is estimated, not perfectly observed
  • bundle-level optimization does not yet include customer-level targeting
  • simulation is not part of this bundle engine itself and should be a later module

Final Statement

The proposed MinTel bundle generation solution is a structured AI-assisted optimization system. It does not try to let an LLM invent telecom bundles from scratch. Instead, it learns from historical bundles, uses the existing Dynamic Pricing Algorithm as the price authority, searches bundle structures using a Genetic Algorithm, subtracts cannibalization risk to protect the current portfolio, and finally uses an LLM to generate the bundle name and commercial wording.

In short, the mathematical core of the system is:

Generate candidate bundle x -> get price p = DP(x) -> predict business popularity B(x) -> compute cannibalization penalty C(x) -> compute final fitness F(x) -> evolve population until best bundles are found -> generate names using LLM

This makes the system technically credible, commercially realistic, and suitable for phased implementation.
